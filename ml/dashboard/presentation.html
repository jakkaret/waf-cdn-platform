รวบรวมและผสานข้อมูลจาก 2 แหล่งหลักเพื่อความสมบูรณ์และทันต่อภัยคุกคามสมัยใหม่:

🌐 แหล่งที่ 1: CSIC 2010 HTTP Dataset (ชุดข้อมูลมาตรฐานวิจัยระดับโลก) ~20,000 Samples
  • ผู้พัฒนา / สถาบันวิจัย: Information Security Group, Spanish National Research Council (CSIC), ประเทศสเปน
  • GitHub Repository ที่ดึงข้อมูล: https://github.com/msudol/Web-Application-Attack-Datasets (ไฟล์ CSVData/csic_final.csv)
  • ลักษณะข้อมูล: บันทึกทราฟฟิก HTTP จริงจากการใช้งานระบบ E-Commerce Web Application (ทั้งการซื้อของปกติและการพยายามเจาะระบบ)
  • การทำ Data Cleaning: กรองแถว Header Anomaly ที่ไม่มี Payload ใน Query/Body ออก เพื่อป้องกันปัญหา Model Poisoning
🚀 แหล่งที่ 2: Data Augmentation & Enhanced Modern Security Dataset ~40,000 Samples

สร้างขึ้นแบบ Programmatically (ผ่านสคริปต์ ml/download_dataset.py) โดยอ้างอิงจากคลัง Payload และมาตรฐานความปลอดภัยสากล:

  • คลังการโจมตี (OWASP Top 10 Payloads ~15,000 ตัวอย่าง):
    • SQLi, XSS, SSRF, SSTI, NoSQL: อ้างอิงจาก PayloadsAllTheThings (swisskyrepo) และ SecLists (danielmiessler)
    • Log4Shell Exploit: อ้างอิงจากฐานข้อมูลช่องโหว่ NIST NVD (CVE-2021-44228)
    • Cloud SSRF Exfiltration: อ้างอิงจาก AWS IMDSv1 (169.254.169.254) และ Google Cloud Metadata (metadata.google.internal)
    • WAF Evasion Mutations: อ้างอิงเทคนิคจาก OWASP Web Security Testing Guide (WSTG) เช่น Double URL Encoding, Case Swapping (uNiOn SeLeCt), Inline Comment (/**/)
  • ทราฟฟิกปกติ (Modern Benign Web & REST API ~25,000 ตัวอย่าง):
    • RESTful API Standards: จำลอง JSON Auth Body, Pagination (page, limit, sort, order), UUID paths (/api/v1/users/{uuid})
    • Real-world E-Commerce Corpus: คำค้นหาสินค้าภาษาไทย/อังกฤษจริง, ฟอร์มติดต่อ, การจัดการตะกร้าสินค้า และ Asset Files ปกติ

💡 ข้อสรุปสำคัญสำหรับนำเสนอ (Key Presentation Takeaways)

  • ความปลอดภัยของผู้ใช้จริงสูงสุด (High Precision 98.39%): เมื่อโมเดลตัดสินใจบล็อก มีโอกาสผิดพลาด (False Alarm) เพียง 1.03% (77 จาก 7,454 ตัวอย่าง) ทำให้มั่นใจได้ว่าจะไม่รบกวนการใช้งานของผู้ใช้ทั่วไป
  • ครอบคลุมทราฟฟิกปกติ (Benign Recall 98.97%): ปล่อยผ่านคำขอที่ถูกต้องได้อย่างมีประสิทธิภาพสูงถึง 98.97%
  • การใช้ฟีเจอร์เชิงโครงสร้าง (Structural Feature Engineering): การสกัดฟีเจอร์ผสมผสานระหว่างคีย์เวิร์ด (`keyword_matches`) และสถิติอักขระ (`special_char_ratio`) ทำให้โมเดลทนทานต่อการหลบเลี่ยง (Evasion Mutations) ได้ดีกว่า Rule แบบตรงตัว
