# ผลทดสอบการตรวจจับของโมเดล Gen 3 ด้วยเครื่องมือ WAF (29/09/2026)

สรุปแบบอ่านง่าย: [คู่มือ WAF Gen 3](https://claude.ai/artifact/326kranMWeArKGfG7Wanxt) · สไลด์: [WAF Gen 3 ML Results](https://claude.ai/artifact/GgK8Ss99hX4ps3ZEkbGPRg) (private)

รันบนเครื่อง local: harness (`waf_test_harness.py`) โหลด `gen3_f_model.onnx`
(sha256 `a7e232…eac8`, threshold 0.8035) ยิงด้วยเครื่องมือ 3 ตัวเข้า `127.0.0.1:8088`
ไม่แตะ VPS วัด **เฉพาะชั้น ML** ที่ตรวจ URL + body ที่ decode แล้วเท่านั้น

เครื่องมือ: GoTestWAF v0.5.10 · sqlmap 1.10.9 · Nuclei v3.11.1

## สรุป

| เครื่องมือ | ยิง | โมเดลบล็อก | อ่านผล |
| :--- | ---: | ---: | :--- |
| GoTestWAF (attack) | 675 | 31.26% (211) | ต่ำเพราะ encoding/ตำแหน่ง ไม่ใช่คุณภาพการจับ |
| GoTestWAF (benign) | 141 | 12.77% FP | true-negative ผ่าน 87.23% |
| sqlmap | 1,227 | 442 (403) | SQLi จริงถูกบล็อกครบ (คะแนนต่ำสุด 0.808); 785 ที่ผ่านคือ baseline `id=1` |
| Nuclei | 6,207 | 3.8% | เกือบทั้งหมดเป็น probe ที่ไม่มี payload |

GoTestWAF overall score = **29.79%** (app-sec TP 31.92% / TN 87.23%)

## ทำไม GoTestWAF ได้ 31%

464 payload ที่หลุด แยกตาม encoding: **Base64 235 (51%)**, URL-encode 189 (41%), Plain 40 (9%)
แยกตามตำแหน่ง: multipart 103, HTML form 89, URL path 81, URL param 79, JSON 78, header/UA 20

พิสูจน์ด้วย payload เดียวกัน (`1' UNION SELECT username,password FROM users--`):

| รูปแบบ | คะแนน | ผล |
| :--- | ---: | :--- |
| plain ใน query | 0.9818 | บล็อก |
| plain ใน form body | 0.9927 | บล็อก |
| Base64 ใน query | 0.0013 | ผ่าน |
| ใน JSON body | 0.2151 | ผ่าน |
| ใน multipart body | 0.3385 | ผ่าน |

โมเดลไม่ decode base64 และไม่ parse JSON/multipart/header — งานนั้นเป็นของ ModSecurity/CRS
ในระบบเต็ม (CRS normalize base64/multipart และอ่าน header ก่อนถึง ML)

## ข้อสรุป

- โมเดลจับ payload ที่มันเห็น (plain ใน query/body) ได้ดีมาก: plain SQLi/XSS 0.98–0.99,
  sqlmap ที่ obfuscate ด้วย tamper ก็ยังจับได้ (มี 2 ตัวที่ `/**/` หนักมากได้ 0.800 เฉียด threshold)
- จุดที่หลุด = base64, JSON/multipart, header, และ probe ที่ไม่มี payload → ชั้น CRS + shield
- ผลนี้ยืนยันการแบ่งหน้าที่ระหว่างชั้น ไม่ใช่ข้อบกพร่องของโมเดล

## วิธีรันซ้ำ

```bash
# harness (serve venv มี onnxruntime + libinjection)
WAF_GEN3_ONNX_PATH=ml/models/gen3/gen3_f_model.onnx PYTHONPATH=. \
  uvicorn ml.security_test.waf_test_harness:app --host 127.0.0.1 --port 8088
# อีก terminal
TOOLS=<tools> bash ml/security_test/run_tests.sh          # nuclei + sqlmap (+ gotestwaf ถ้ามี config)
# gotestwaf ต้องชี้ config + testcases (build จาก source ไม่ฝังมา):
gotestwaf --url http://127.0.0.1:8088 --configPath <src>/config.yaml --testCasesPath <src>/testcases \
  --blockStatusCodes 403 --passStatusCodes 200 --reportFormat json --reportPath ml/security_test/reports/gotestwaf
```

- sqlmap รอบ F/F-noenc ส่ง payload ชุดเดียวกัน 1,066 ตัว (มากกว่ารอบก่อน) จึงเทียบ % กับ 2 แถวบนตรงๆ ไม่ได้
