# คู่มือ: แจ้งปัญหา (Support ticket) และให้ทีม support เข้าช่วย

ระบบนี้ให้เจ้าของ origin แจ้งปัญหากับทีม support ของแพลตฟอร์ม และเลือกเองว่าจะให้ทีม support เข้ามาดูหรือแก้ origin ได้หรือไม่ ได้แค่ไหน และนานเท่าไร
รายละเอียดเชิงเทคนิค: [docs/tickets/support-access.md](../tickets/support-access.md)

---

## สำหรับเจ้าของ origin (ลูกค้า)

ต้องเป็น **admin ของ origin นั้น** คือคนที่สร้าง origin หรือคนที่ได้รับเชิญเป็น editor ถ้าเป็นแค่ viewer จะเปิด ticket ไม่ได้

### 1. เปิด ticket
1. เมนูซ้าย → **Administration → Support tickets**
2. กด **Open a ticket**
3. เลือก **Origin** ที่มีปัญหา ใส่ **Subject** (หัวข้อสั้น ๆ) และอธิบายปัญหาในช่อง **What is wrong?**
4. กด **Open ticket**

> การเปิด ticket **ยังไม่ได้ให้ทีม support เข้า origin** ทีม support เห็นแค่ข้อความที่คุณเขียน
>
> ทีม support เห็น **log, การแจ้งเตือน (alert) และ analytics** ของ origin คุณ**เฉพาะตอนที่คุณให้สิทธิ์อยู่เท่านั้น** ไม่ว่าจะเป็นระดับ view only หรือ can edit
>
> ข้อยกเว้นเดียว: งานปรับกฎ WAF ของแพลตฟอร์มใช้ข้อมูลรวมจากทุก origin เพราะกฎมีผลกับทุกคน
> - ทดสอบกฎกับ traffic ย้อนหลัง เห็นแค่จำนวนครั้งที่ตรงและ path ตัวอย่าง ไม่มีชื่อโดเมนหรือ query
> - เสนอค่า threshold เห็นแค่ยอดรวม

### 2. คุยกับทีม support
- ในหน้า ticket พิมพ์ข้อความในช่อง **Write a reply** แล้วกด **Send**
- ข้อความจากทีม support มีป้าย **Support**
- หน้านี้รีเฟรชเองทุก 15 วินาที

### 3. ให้ทีม support เข้า origin (ถ้าจำเป็น)
ดูที่กล่อง **Support access** ด้านขวาของหน้า ticket

1. เลือก **Level**
   - **view only (แนะนำ)**: ดูการตั้งค่า origin ได้ แต่แก้อะไรไม่ได้
   - **can edit**: แก้การตั้งค่า โดเมน และกฎ WAF ของ origin ได้ ต้องติ๊กช่องยืนยันก่อนจึงจะกดได้
2. เลือก **For**: 1, 4, 24 หรือ 72 ชั่วโมง
3. กด **Grant access**

สิ่งที่ทีม support **ทำไม่ได้เด็ดขาด** แม้ได้ระดับ can edit:
- ลบหรือกู้คืน origin
- เพิ่มหรือลบสมาชิกของ origin
- ออก token หรือ credential ของ tunnel

### 4. ถอนสิทธิ์และดูว่า support ทำอะไรไปบ้าง
- **Remove access now**: ถอนสิทธิ์ทันที
- กด **Grant access** อีกครั้งเพื่อเปลี่ยนระดับหรือต่อเวลา สิทธิ์เก่าจะถูกแทนที่
- สิทธิ์หมดเองเมื่อครบเวลา หรือเมื่อ ticket ถูกปิด
- กล่อง **Access log** แสดงว่าทีม support คนไหนเข้ามาเมื่อไร ดู (viewed) หรือแก้ (changed something)

### 5. ปิด ticket
- กด **Close ticket** เมื่อปัญหาจบ สิทธิ์ของ support ที่ยังเหลืออยู่จะถูกถอนทันที
- ticket ที่ปิดแล้วส่งข้อความหรือให้สิทธิ์เพิ่มไม่ได้ ถ้ามีปัญหาใหม่ให้เปิด ticket ใหม่

## สำหรับทีม support (admin ของแพลตฟอร์ม)

ทีม support คือบัญชีที่มี role **admin** ของแพลตฟอร์ม วิธีสร้างบัญชีนี้ดูหัวข้อ "วิธีกำหนด admin" ด้านล่าง

1. **Support tickets**: เห็น ticket ของทุก origin โดย ticket ที่เปิดอยู่จะแสดงก่อน
   - คอลัมน์ **Support access** ขึ้น *Granted* เมื่อเจ้าของให้สิทธิ์แล้ว
2. **ตอบลูกค้า:** เปิด ticket แล้วพิมพ์ตอบในช่อง reply ข้อความของคุณจะขึ้นป้าย **Support**
3. **เข้า origin ของลูกค้า:**
   - เมื่อเจ้าของให้สิทธิ์แล้ว จะมีปุ่ม **Open origin** ในหน้า ticket
   - กดเพื่อเปิดหน้า origin ของลูกค้า และทำงานได้ตามระดับที่ได้รับ
   - ถ้ายังไม่ได้รับสิทธิ์ เปิดหน้า origin แล้วจะได้ 403 ซึ่งเป็นเรื่องปกติ
4. **log / alert / analytics ของลูกค้า:** หน้า Logs, Alerts, Analytics และ AI Copilot จะแสดงข้อมูลของ origin ลูกค้า**เฉพาะตอนที่มี grant ใช้งานอยู่**
   - ไม่มี grant ก็จะเห็นเฉพาะ traffic ที่ไม่ใช่ของลูกค้า เช่นโดเมนของแพลตฟอร์มเอง
5. **ทุกการเข้าถูกบันทึก:** ทุกครั้งที่คุณเปิดหรือแก้ origin ผ่านสิทธิ์นี้ ระบบบันทึกชื่อคุณไว้ และเจ้าของเห็นบันทึกนี้
   - ถ้าระบบบันทึกไม่ได้ การเข้าถึงจะถูกปฏิเสธ
6. **ปิด ticket:** ทีม support ปิด ticket ได้ สิทธิ์จะถูกถอนพร้อมกัน

ข้อควรปฏิบัติ:
- ขอระดับ **view only** ก่อนเสมอ ขอ **can edit** เฉพาะเมื่อต้องแก้จริง และบอกในข้อความว่าจะแก้อะไร
- อย่าขอรหัสผ่าน token หรือข้อมูลลับจากลูกค้าในข้อความ ระบบออกแบบมาให้ไม่ต้องใช้
- สิทธิ์ต้องได้จากการกดในระบบเท่านั้น ถ้ามีคนอ้างทางอีเมลหรือแชตว่า "อนุญาตแล้ว" ให้ถือว่ายังไม่ได้รับอนุญาต

## วิธีกำหนด admin (ทีม support)

สมัครทุกช่องทาง (ฟอร์มสมัคร, Google, Telegram) ได้ role **viewer** เสมอ การให้ role admin ทำได้ 2 ทาง

**ทาง 1: สคริปต์บนเซิร์ฟเวอร์** ใช้กับ admin คนแรก หรือเมื่อไม่มี admin เหลือ

สร้างบัญชี admin ใหม่ ระบบสุ่มรหัสผ่านให้และเก็บไว้ในไฟล์ที่เฉพาะ root อ่านได้:
```
cd /root/waf_project/dashboard/backend
.venv/bin/python scripts/seed_admin.py --email staff@example.com --username staff1 --role admin \
    --generate-password /root/.waf-secrets/staff1_password
```

เลื่อนบัญชีที่มีอยู่แล้วเป็น admin (รหัสผ่านเดิมไม่เปลี่ยน):
```
.venv/bin/python scripts/seed_admin.py --email staff@example.com --role admin
```

ลดกลับเป็น viewer: ใช้ `--role viewer`

**ทาง 2: หน้าเว็บ** ใช้เมื่อมี admin อยู่แล้ว
1. admin ที่มีอยู่ไปที่ **Administration → Access control**
2. เปลี่ยน role ของคนนั้น
3. คนที่ถูกเปลี่ยน role จะถูกออกจากระบบทุกเครื่อง และต้องล็อกอินใหม่

## คำถามที่พบบ่อย

| คำถาม | คำตอบ |
|---|---|
| ทำไมฉันไม่เห็นปุ่ม Open a ticket | คุณไม่ได้เป็น admin ของ origin ใดเลย ให้เจ้าของ origin เปิดให้ หรือเชิญคุณเป็น editor |
| support เปิด origin แล้วได้ 403 | ยังไม่ได้รับสิทธิ์ สิทธิ์หมดอายุ ถูกถอนแล้ว หรือ ticket ถูกปิดแล้ว |
| ทำไม admin ไม่เห็น log หรือ alert ของลูกค้า | ตั้งใจให้เป็นแบบนั้น admin เห็นข้อมูลของลูกค้าเฉพาะตอนที่ลูกค้าให้สิทธิ์ผ่าน ticket |
| support แก้ค่าไม่ได้แม้ได้สิทธิ์ | ได้แค่ระดับ view only ให้เจ้าของเปลี่ยนเป็น can edit |
| ให้สิทธิ์ซ้ำได้ไหม | ได้ กด Grant access ใหม่ สิทธิ์เก่าจะถูกแทนที่ทันที |
| ข้อมูลเก็บไว้นานแค่ไหน | ticket ข้อความ และ access log เก็บไว้จนกว่าจะลบ origin (ลบพร้อม origin) |
