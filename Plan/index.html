Function Division

การแบ่ง Module & Function

แบ่งระบบออกเป็น 8 Module หลัก แต่ละ Module มีหน้าที่ชัดเจน

Module 1: Authentication & User Management

Core

จัดการ User registration, login, JWT auth และ ownership ของ origin

POST register()

สมัครสมาชิกใหม่ — รับ email, password, name

Input
{ email, password, name }
Output
{ user_id, token }
Logic
  • Validate email format & uniqueness
  • Hash password (bcrypt)
  • Create user record
  • Issue JWT token
POST login()

Login — รับ email, password → return JWT

Input
{ email, password }
Output
{ access_token, refresh_token }
Logic
  • Verify credentials
  • Generate JWT (access + refresh)
  • Record login timestamp
GET get_profile()

ดึงข้อมูล profile ของ user ที่ login อยู่

Input
JWT Token (Header)
Output
{ id, email, name, origins[] }
MIDDLEWARE verify_ownership()

ตรวจสอบว่า user เป็น admin ของ origin นั้นจริง

Logic
  • Decode JWT → get user_id
  • Check origin.admin_user_id == user_id
  • Reject if not owner (403)

Module 2: Origin Management

Critical

CRUD Web Origin — User กรอก IP ของเว็บ Origin มา แล้วระบบสร้าง reverse proxy config ให้

POST create_origin()

⭐ Core Function — สร้าง Web Origin ใหม่

Input
{ origin_ip, origin_port, label }
Output
{ origin_id, status: "pending" }
Logic
  • Validate IP format (IPv4/IPv6)
  • Check IP reachability (health check)
  • Set current user as admin
  • Create Nginx upstream config
  • Initialize WAF rules for this origin
GET list_origins()

แสดงรายการ origin ทั้งหมดที่ user เป็น admin

Output
[ { origin_id, ip, label, status, domains[] } ]
PUT update_origin()

แก้ไข IP หรือ port ของ origin (owner เท่านั้น)

Logic
  • Verify ownership
  • Validate new IP
  • Update Nginx upstream
  • Reload Nginx config
DELETE delete_origin()

ลบ origin ออกจากระบบ (cleanup ทุกอย่าง)

Logic
  • Remove Nginx config
  • Revoke SSL certificates
  • Remove WAF rules
  • Purge CDN cache
  • Delete database records
GET health_check_origin()

ตรวจสอบว่า origin ยัง online อยู่

Logic
  • HTTP GET → origin_ip:origin_port
  • Timeout 5s → mark as "down"
  • Update status in DB

Module 3: Domain & DNS Verification

Critical

จัดการ Domain — User กรอกชื่อ Domain แล้วระบบแจ้ง DNS record ที่ต้อง set ให้ชี้มาที่ CDN ของเรา

POST add_domain()

⭐ Core Function — ผูก Domain กับ Origin

Input
{ origin_id, domain_name }
Output
{ domain_id, cname_target, verification_token }
Logic
  • Validate domain format
  • Check domain not already in use
  • Generate CNAME target (e.g. proxy.our-cdn.com)
  • Generate TXT verification token
  • Return DNS instructions to user
POST verify_dns()

⭐ Core Function — ตรวจ DNS ว่าชี้มาหาเราหรือยัง

Logic
  • DNS lookup CNAME → ต้องชี้มา CDN IP ของเรา
  • DNS lookup TXT → ต้องมี verification token
  • ถ้าผ่าน → mark dns_verified = true
  • Trigger SSL provisioning อัตโนมัติ
GET get_dns_instructions()

แสดงคำสั่ง DNS ที่ user ต้อง set ที่ Registrar ของตัวเอง

Output Example
Type: CNAME Name: @ Value: proxy.our-cdn.com Type: TXT Name: _verify Value: waf-verify=abc123

Module 4: SSL / Auto-HTTPS

Auto

ออก SSL Certificate อัตโนมัติเมื่อ DNS verified แล้ว ใช้ Let's Encrypt + ACME Protocol

AUTO provision_ssl()

⭐ Core Function — ออก SSL cert อัตโนมัติหลัง DNS verified

Logic
  • Triggered เมื่อ dns_verified = true
  • ใช้ Certbot / ACME client
  • ขอ cert จาก Let's Encrypt
  • HTTP-01 challenge (via .well-known/acme-challenge)
  • บันทึก cert + key paths ลง DB
  • Update Nginx SSL config
  • Reload Nginx
CRON renew_ssl()

Auto-renew cert ก่อนหมดอายุ 30 วัน

Logic
  • Cron job ทุกวัน ตรวจ cert ที่จะหมดอายุ
  • Renew ผ่าน certbot renew
  • Reload Nginx หลัง renew สำเร็จ
  • Alert ถ้า renew ล้มเหลว
GET get_ssl_status()

ดูสถานะ SSL ของแต่ละ domain

Output
{ status, issuer, expires_at, auto_renew }

Module 5: WAF Configuration

Security

จัดการ WAF rules per origin — ModSecurity + OWASP CRS + Custom rules

GET get_waf_config()

ดึง WAF config ของ origin

Output
{ paranoia_level, anomaly_threshold, custom_rules[], blocked_ips[] }
PUT update_waf_config()

ปรับค่า WAF — paranoia level, anomaly threshold

Logic
  • Validate paranoia level (1-4)
  • Update ModSecurity config per origin
  • Reload Nginx/WAF
POST add_custom_rule()

เพิ่ม WAF rule สำหรับ origin นี้โดยเฉพาะ

POST block_ip()

Block IP สำหรับ origin นี้

Module 6: CDN & Cache Management

Performance

จัดการ cache settings per origin — TTL, purge, bypass rules

GET get_cache_config()

ดึง cache settings ของ origin

Output
{ cache_ttl, static_ttl, bypass_rules[], cache_status }
POST purge_cache()

Purge cache ของ origin — all หรือเฉพาะ URL

PUT update_cache_config()

ปรับ TTL, bypass rules สำหรับ origin

Module 7: Nginx Config Generator

Infrastructure

สร้าง/อัปเดต Nginx config อัตโนมัติเมื่อ origin หรือ domain เปลี่ยน

INTERNAL generate_nginx_config()

⭐ Core Function — สร้าง Nginx server block จาก template

Logic
  • ใช้ Jinja2 template → render server block
  • server_name = domain_name
  • proxy_pass = origin_ip:origin_port
  • SSL cert/key paths
  • WAF include (per origin)
  • Cache settings
INTERNAL reload_nginx()

Test config แล้ว reload Nginx

Logic
  • nginx -t (test config syntax)
  • nginx -s reload
  • Rollback ถ้า test fail

Module 8: Monitoring & Alerting

Observability

ติดตามสถานะ origin, traffic, WAF events และ alert ผ่าน Telegram

GET get_dashboard_stats()

ข้อมูลสรุป — total requests, blocked, cache hit rate

GET get_waf_logs()

WAF attack logs — severity, rule matched, source IP

CRON origin_health_check()

ตรวจ origin ทุก 1 นาที — alert ถ้า down

EVENT send_telegram_alert()

แจ้งเตือนผ่าน Telegram Bot เมื่อมี critical event

Full System Flow

Flow การทำงานระบบ (End-to-End)

ตั้งแต่ User สมัครสมาชิก จนถึง Request วิ่งผ่านระบบได้จริง

🚀 Setup Flow — ตั้งค่าระบบครั้งแรก
1
👤 User
POST /api/auth/register
{ email, password, username }
→ JWT token + DynamoDB waf_users record
2
👤 User
POST /api/origins
{ origin_ip: "1.2.3.4", port: 80, label: "My Site" }
→ สร้าง record ใน waf_origins + สร้าง Nginx upstream block
3
⚙️ Backend
Health Check Origin IP
HTTP GET → 1.2.3.4:80, timeout 5s
→ status: "online" หรือ "unreachable"
4
👤 User
POST /api/origins/:id/domains
{ domain_name: "example.com" }
→ สร้าง record + generate verification_token + return DNS instructions
5
👤 User
ไปที่ Domain Registrar
Set CNAME: example.com → proxy.waf-cdn.com
Set TXT: _verify → waf-verify=<token>
→ DNS propagate (ใช้เวลา 5 min - 24 hr)
6
👤 User
POST /api/domains/:id/verify
Trigger DNS check
→ Backend query DNS: CNAME ✓ + TXT ✓ → dns_verified = true
7
⚙️ Backend (Auto)
SSL Provisioning Trigger
certbot certonly --webroot -d example.com
→ Let's Encrypt ออก cert → บันทึก paths ใน DB
8
⚙️ Backend (Auto)
Generate Nginx Config
Jinja2 render server block → write to /conf.d/example.com.conf
→ nginx -t ✓ → nginx -s reload ✓
✓
🎉 เสร็จ!
example.com พร้อมใช้งาน
HTTPS active • WAF enabled • CDN cache on
→ Traffic วิ่งผ่าน DNS → CDN → WAF → origin ได้แล้ว
⚡ Request Flow — Traffic จริงเมื่อ User เข้าเว็บ
1
🖥️ Browser
ผู้ใช้พิมพ์ https://example.com
→ Browser query DNS resolver
2
🌐 DNS
CNAME lookup: example.com
→ proxy.waf-cdn.com → CDN edge IP (ใกล้ที่สุด)
→ Return IP address ของ CDN edge node
3
⚡ CDN Edge
รับ HTTPS request → SSL termination
ตรวจ cache: มี? → ตอบกลับทันที (CACHE HIT)
→ ถ้า HIT: ตอบเลย (ไม่ผ่าน WAF) ถ้า MISS: ส่งต่อ WAF
4
🛡️ WAF
ModSecurity + OWASP CRS analysis
ตรวจ SQLi, XSS, RCE, path traversal, ...
→ ถ้าอันตราย: block 403 ถ้าปกติ: proxy_pass → origin
5
🖥️ Web Origin
รับ request → process → ตอบ response
origin_ip:origin_port
→ Response ส่งกลับผ่าน WAF → CDN (store cache) → Browser
6
📝 Log Pipeline
log_forward_worker
อ่าน /var/log/nginx/access.json ทุก 5s
→ ส่งข้อมูลใน DynamoDB → Dashboard อัปเดต
🔒 Auto-HTTPS Flow — SSL ออกอัตโนมัติ
1
⚙️ Backend
detect: dns_verified = true
Triggered จาก POST /api/domains/:id/verify
→ เรียก provision_ssl(domain_id)
2
⚙️ Certbot
certbot certonly --webroot
-d example.com --webroot-path /var/www/acme
→ Certbot ร้องขอ challenge จาก Let's Encrypt
3
🌐 Let's Encrypt
HTTP-01 Challenge
GET example.com/.well-known/acme-challenge/<token>
→ Nginx serve challenge file → LE verify ✓
4
⚙️ Backend
บันทึก cert paths
/etc/letsencrypt/live/example.com/fullchain.pem
→ อัปเดต DB: ssl_status = "active", expires_at = 90 วัน
5
⚙️ Nginx Config Gen
Render Jinja2 template → เพิ่ม SSL block
ssl_certificate fullchain.pem; ssl_certificate_key privkey.pem;
→ nginx -t ✓ → nginx -s reload → HTTPS active!
6
🔄 Cron Job (daily)
